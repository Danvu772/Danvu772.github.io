Building a Meme Bot That Learns Your Server

python
discord
fun
A Discord bot that generates memes from your server’s own message history — because the jokes already happened.
Author

Dan Vu

Published

April 22, 2026

Every friend group has its own language. Inside jokes, recurring bits, moments that only land if you were there. I wanted to see if I could bottle that — so I built a Discord bot that generates memes entirely from my server’s own history.

Code is on GitHub.

The Idea

Tenor GIFs and text messages don’t exist in a vacuum. When someone drops a GIF in a chat, there’s usually something said right around the same time — a reaction, a setup, a punchline. Pair them and you get something that reads like a real meme. The humor is baked in because both halves are authentic to the server.

The bot crawls your message history, finds every Tenor GIF, grabs the text message sent immediately before or after it, and stores the pair. When you run $generatememe, it picks a random pair, fetches the GIF, and stamps the text over every frame in Impact font — the universal language of meme formatting.

How It’s Built

The stack is intentionally minimal: Python, discord.py, Pillow for image processing, and Docker for packaging.

The Crawl

Runs on first boot. The bot walks every readable channel, pulls up to 10,000 messages per channel, and for each Tenor link it finds, randomly checks the message immediately before or after it. If that neighbor is clean text — no URLs, not empty — it’s a valid pair and gets stored in a JSON index. A weekly background task via discord.ext.tasks runs an incremental refresh, fetching only new messages since the last crawl per channel.

The Image Processing

The most satisfying part. Pillow’s ImageSequence iterator lets you process animated GIFs frame by frame. For each frame:

  • Font size scales proportionally to image width
  • Text wraps to fit
  • The outline is drawn by rendering the same text at every pixel offset in a small grid around the position, then white text on top

Brute-force outline rendering, but it produces exactly the right look.

frames = []
for frame in ImageSequence.Iterator(gif):
    frame = frame.convert("RGBA")
    draw = ImageDraw.Draw(frame)
    # draw outline
    for dx in range(-outline_size, outline_size + 1):
        for dy in range(-outline_size, outline_size + 1):
            draw.text((x + dx, y + dy), text, font=font, fill="black")
    # draw white text
    draw.text((x, y), text, font=font, fill="white")
    frames.append(frame)

The Pairing Logic

Rather than trying to find the “best” adjacent message, the bot randomly picks one direction — before or after — and commits to it. If the chosen neighbor isn’t clean text, the pair is skipped entirely. This keeps the index honest: every entry is a real pairing that happened naturally in conversation, not a best-effort reconstruction.

What I Learned

Scraping Tenor is fragile. The bot parses page HTML to find the actual GIF CDN URL, which means it breaks if Tenor ever restructures their markup. A proper API integration would be more stable, but scraping works for a personal project and keeps the dependency count low.

Docker volume mounts matter more than you’d think. The bot runs in a container, which means any files written at runtime — the meme index, crawl state — need to be volume-mounted if you want them to survive rebuilds. Otherwise every image rebuild wipes the index and forces a full re-crawl. Getting the dev workflow right (hot-reload via Docker’s watch mode, separate dev/prod compose configs) took more iteration than the bot itself.

The Result

It works better than expected. The memes it generates are genuinely funny in a way that an AI meme generator isn’t — because the humor is already baked in. The bot isn’t creating jokes, it’s surfacing ones that already happened.

The codebase is small enough to be a weekend project, specific enough to be interesting, and weird enough to be worth sharing.
